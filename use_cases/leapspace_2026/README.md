# LeapSpace 2026, two-step contact reason then root cause by access type

> Replaces the first LeapSpace study, [`leapspace_legacy`](../leapspace_legacy/README.md).
> The 8 contact reasons defined here are reused unchanged in
> [`leapspace_2026_email_reg`](../leapspace_2026_email_reg/README.md).

## Business question
Give every LeapSpace ticket a contact reason, and for the two access categories, say why the
customer could not get in. The revised taxonomy (with written definitions and evidence signals
for every category) came from the business in `copy_leapspace_enriched.xlsx`; this run applies it to
all 2026 tickets and checks it against a small set of human-labelled tickets.

## Data
- **Source:** LeapSpace support ticket and thread extraction, collapsed to one conversation per ticket.
- **Period and size:** 1,505 tickets, 2025-10-24 to 2026-07-30 (one ticket from 2025; the rest 2026).
  Mostly Web (985) and CSS Email (306).
- **Location:** `data/leapspace_collapsed_2026.csv` (linked to the local data archive, never committed).
- **Human labels:** the *List of tickets and examples* tab of `copy_leapspace_enriched.xlsx`:
  50 tickets with a contact reason, 40 of them also with a root cause.
- **Preparation:** [`notebooks/06_leapspace_2026_two_step.ipynb`](notebooks/06_leapspace_2026_two_step.ipynb)
  builds the definition, runs a smoke test, splits the access subsets and joins the results.

## Approach
- **Definition:** [`definitions/leapspace_2026_pipeline_definition.xlsx`](definitions/leapspace_2026_pipeline_definition.xlsx),
  generated by [`scripts/build_leapspace_2026_definition.py`](scripts/build_leapspace_2026_definition.py),
  which copies the business's guidance text into the taxonomy word for word.
- **Steps / modules:**
  1. `leapspace_contact_reason` (LCR): one of 8 contact reasons, on **every** ticket. The prompt
     says to decide *who* is asking before *what*: Elsevier staff asking for someone else are always
     *Internal staff access*.
  2. Root cause, only for the two access categories:
     - 2a `leapspace_rc_institutional` (RCI): 12 root causes, for *Institutional user cannot access*.
     - 2b `leapspace_rc_individual` (RCU): 9 root causes, for *User not able to access*.
  The other six contact reasons get no root cause, by design. Each module returns a code, a
  justification and a quoted piece of evidence.
- **Profiles:**
  - [`profiles/leapspace_2026_step1_contact_reason.json`](profiles/leapspace_2026_step1_contact_reason.json): step 1, all tickets.
  - [`profiles/leapspace_2026_step2_institutional.json`](profiles/leapspace_2026_step2_institutional.json): step 2a, reads `runs/intermediate/leapspace_2026_subset_institutional.csv`.
  - [`profiles/leapspace_2026_step2_individual.json`](profiles/leapspace_2026_step2_individual.json): step 2b, reads `runs/intermediate/leapspace_2026_subset_individual.csv`.
  - All use batch size 5, concurrency 2, up to 40,000 characters per ticket, cost tracking on.
- **Enhancements:** a smoke test on the 50 human-labelled tickets before the full run, routed by
  the *predicted* contact reason so it tests the whole flow. Feedback examples are deliberately
  **off** (see Known issues).

## Taxonomy at a glance
- **Contact reason (8, one leaf each):** User not able to access; Institutional user cannot access;
  Internal staff access; Subscription cancellation and/or refund; Subscription request (including
  resubscription and trial); Not enough info; Billing; Other / not covered (added for this run).
- **Institutional root causes (12):** Technical issue – downtime, IP confusion, Email
  blocked/blacklisted, Not within IP range, SD AI migration gap, Access method not set up (SSO),
  Institution not entitled, Technical issue – Cortex, Not enough info, Change org issue, Proxy issue,
  Error 403.
- **Individual root causes (9):** General Troubleshooting steps, Not enough info, LeapSpace not
  launched yet, SD AI migration gap, User mistakenly thought it was subscribed, Cache and cookies,
  Change org issue, Lack of user guidance, Session not refreshed after purchase.

## How to re-run
```bash
cd use_cases/leapspace_2026
rca validate
rca build
rca run --profile profiles/leapspace_2026_step1_contact_reason.json --dry-run   # check, then run without --dry-run
# The notebook (section 6) writes the two subset CSVs from the step-1 output, then:
rca run --profile profiles/leapspace_2026_step2_institutional.json
rca run --profile profiles/leapspace_2026_step2_individual.json
```
Run the two step-2 profiles one after the other, not in parallel. The notebook (section 8 to 10)
joins everything into the final workbook.

## Results
Run on 2026-08-03. Deliverable: `runs/output/leapspace_2026_two_step.xlsx` (sheets: All tickets,
Access tickets, Contact reason summary, Root cause summary, Eval vs human labels, Taxonomy used),
plus `leapspace_2026_two_step_full_text.csv` with untruncated conversations.

- **Contact reason (1,505 tickets):** Subscription cancellation and/or refund 445 (29.6%),
  Institutional user cannot access 267 (17.7%), User not able to access 247 (16.4%),
  Other / not covered 172 (11.4%), Internal staff access 171 (11.4%), Subscription request 104 (6.9%),
  Billing 58 (3.9%), Not enough info 41 (2.7%).
- **Institutional root cause (267):** Institution not entitled 85 (31.8%), Access method not set up
  (SSO) 81 (30.3%), Not within IP range 31 (11.6%), Not enough info 18, downtime 15, others under 10 each.
- **Individual root cause (247):** Cache and cookies 58 (23.5%), Session not refreshed after
  purchase 45 (18.2%), User mistakenly thought it was subscribed 39 (15.8%), Not enough info 34,
  General Troubleshooting steps 29, Lack of user guidance 26, others under 10 each.
- **Against human labels** (38 labelled tickets present in the data): contact reason **76.3%**
  (29/38); root cause **33.3%** (5/15 correctly routed access tickets). The sample is small and
  skewed, so treat it as a sanity check, not a precision estimate. On all 50 labelled tickets the
  smoke test scored 68% for contact reason.

## Lessons and reuse tips
- **Split root cause into one module per parent category** when the same label means different
  things in different places (here *Not enough info*, *Change org issue*, *SD AI migration gap*).
  Each prompt then only lists its own options, so cross-category mistakes are impossible.
- **Definitions plus "strong signals" and "do not use as evidence" text** in the taxonomy are the
  main change from the label-only legacy version (68.7% contact reason in k-fold there). The two
  scores use different test tickets, so they are not a strict comparison.
- **Smoke-test on labelled tickets first.** It costs a few percent of the full run and catches
  prompt problems before spending.
- Excel cells stop at 32,767 characters: 8 conversations were truncated in the workbook, so ship a
  companion CSV with the full text.
- Copy this layout (step 1 on everything, step 2 on routed subsets) for any "reason, then cause"
  request.

## Known issues
- `rca validate`: no errors, no warnings.
- **Feedback examples are off.** `feedback/leapspace` holds 115 corrections coded with the old
  `CR1.1`-`CR8.4` codes from [`leapspace_legacy`](../leapspace_legacy/README.md), which do not exist
  here. Re-coding them to the LCR / RCI / RCU codes is the cheapest likely accuracy gain.
- Root-cause accuracy is still low and measured on only 15 tickets. Two human root causes (*RegID*,
  *UI topic*) have no equivalent in this taxonomy.
- *Other / not covered* took 11.4% of tickets; worth a read to see whether a missing category is
  hiding there.
- The build script and the notebook read `data/copy_leapspace_enriched.xlsx`, which is archived under
  `leapspace_legacy/data/`, not this use case's `data/`. Copy or link it before rebuilding.
- The notebook still has steps to back up and restore a *shared* `pipeline_config.json` from the old
  single-repo layout; each use case now has its own `generated/` folder.
